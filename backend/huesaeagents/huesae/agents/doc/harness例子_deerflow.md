# DeerFlow 意图识别与工具选择机制详解

> 本文档通过多个场景示例，详细说明 DeerFlow 如何在**不依赖 bash/沙箱**的情况下完成用户请求。

---

## 核心设计哲学

DeerFlow 的核心理念是：**工具选择由 LLM 决定**，系统只负责提供工具列表和描述。

```
用户请求 ──▶ 系统提示词 ──▶ LLM 推理 ──▶ 工具调用 ──▶ 结果返回
              (工具描述)      (决策过程)     (MCP/内置/社区)
```

---

## 场景一：网页内容提取（Jina AI + MCP）

### 用户请求
> "帮我提取这个网页的主要内容，并总结成要点：https://example.com/article"

### 工具配置
假设配置了 `jina_ai` MCP 工具：

```yaml
# config.yaml 或 MCP server 配置
mcpServers:
  jina_ai:
    enabled: true
    type: stdio
    command: npx
    args: ["-y", "@jinaai/mcp-server-jina"]
```

### LLM 可用工具
```
- read_url(url)      # Jina MCP 工具 - 提取网页内容
- summarize(text)     # 内置或其他 MCP
- present_files()    # 内置工具
```

### 执行流程

```
┌──────────────────────────────────────────────────────────────────────┐
│ 用户请求                                                             │
│ "帮我提取这个网页的主要内容，并总结成要点：https://example.com/article" │
└──────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌──────────────────────────────────────────────────────────────────────┐
│ LLM 推理                                                             │
│                                                                     │
│ 工具选择分析:                                                        │
│ - 用户需要提取网页内容 → 需要 read_url 工具                           │
│ - 用户需要总结 → 需要 summarize 工具                                 │
│                                                                     │
│ 决策:                                                               │
│ Step 1: read_url("https://example.com/article")                     │
│         → Jina MCP 服务器处理，返回网页正文                           │
│                                                                     │
│ Step 2: summarize(上一步的文本内容)                                 │
│         → LLM 自身处理或调用总结工具                                  │
│                                                                     │
└──────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌──────────────────────────────────────────────────────────────────────┐
│ 工具执行                                                             │
│                                                                     │
│ read_url:                                                            │
│     MCP Client ──▶ Jina MCP Server ──▶ Jina Reader API               │
│                          │                                           │
│                          ▼                                           │
│                    返回提取的正文 HTML → 纯文本                       │
│                                                                     │
│ summarize:                                                           │
│     LLM 根据提取的文本生成摘要                                        │
│                                                                     │
└──────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌──────────────────────────────────────────────────────────────────────┐
│ 返回结果                                                             │
│                                                                     │
│ ## 网页内容摘要                                                       │
│                                                                     │
│ 1. 要点一：...                                                       │
│ 2. 要点二：...                                                       │
│ 3. 要点三：...                                                       │
│                                                                     │
│ [原文链接](https://example.com/article)                              │
└──────────────────────────────────────────────────────────────────────┘
```

### 关键点
- **无 bash 调用**：Jina MCP 工具直接封装了网页抓取逻辑
- **MCP 抽象**：LLM 不知道底层如何实现，只调用工具接口

## 场景二：多源网页搜索与内容获取（Tavily + Firecrawl）

### 用户请求
> "搜索最近关于 AI Agent 的最新进展，找出 3 篇最相关的文章并提取要点"

### 工具配置
```yaml
# 社区工具已启用
community:
  tavily:
    enabled: true
  firecrawl:
    enabled: true
```

### LLM 可用工具
```
- tavily_search(query, max_results=5)    # 搜索工具
- firecrawl_scrape(url)                 # 深度抓取工具
- present_files()                       # 内置 - 展示结果
```

### 执行流程

```
┌──────────────────────────────────────────────────────────────────────┐
│ 用户请求                                                             │
│ "搜索最近关于 AI Agent 的最新进展..."                                 │
└──────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌──────────────────────────────────────────────────────────────────────┐
│ LLM 推理                                                             │
│                                                                     │
│ 决策:                                                               │
│ Step 1: tavily_search("AI Agent 最新进展 2024", max_results=5)      │
│         → 返回 5 篇相关文章的标题、摘要、URL                          │
│                                                                     │
│ Step 2-4: 对每篇相关文章                                              │
│     firecrawl_scrape(url) → 提取完整内容                            │
│                                                                     │
│ Step 5: present_files() 或直接返回文字摘要                            │
│                                                                     │
└──────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌──────────────────────────────────────────────────────────────────────┐
│ 工具执行细节                                                          │
│                                                                     │
│ tavily_search:                                                       │
│     deerflow.community.tavily ──▶ Tavily API                         │
│     返回: [{title, url, snippet}, ...]                               │
│                                                                     │
│ firecrawl_scrape:                                                    │
│     deerflow.community.firecrawl ──▶ Firecrawl API                   │
│     返回: {content, markdown, metadata}                              │
│                                                                     │
└──────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌──────────────────────────────────────────────────────────────────────┐
│ 返回结果                                                             │
│                                                                     │
│ ## AI Agent 最新进展                                                  │
│                                                                     │
│ ### 文章 1: [标题]                                                   │
│ **来源**: [URL]                                                      │
│ **要点**:                                                            │
│ - 要点 1...                                                          │
│ - 要点 2...                                                          │
│                                                                     │
│ ### 文章 2: [标题]                                                   │
│ ...                                                                 │
└──────────────────────────────────────────────────────────────────────┘
```

### 关键点
- **社区工具**：Tavily 和 Firecrawl 是 DeerFlow 内置集成的搜索/抓取服务
- **工具链**：搜索 → 抓取 → 总结，是典型的工具组合模式

## 场景三：文件展示与交互（present_files + ask_clarification）

### 用户请求
> "我已经上传了一个 CSV 文件，帮我分析一下数据并生成图表"

### 前置条件
```
用户已上传: sales_data.csv (上传到 thread_id 的 uploads 目录)
```

### LLM 可用工具
```
- read_file(path)                # 读取上传的 CSV
- present_files(paths)            # 展示生成的文件
- ask_clarification(question)    # 请求用户澄清
- view_image(image_path)         # 查看图片（需 vision 支持）
```

### 执行流程

```
┌──────────────────────────────────────────────────────────────────────┐
│ 用户请求                                                             │
│ "帮我分析一下数据并生成图表"                                          │
└──────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌──────────────────────────────────────────────────────────────────────┐
│ UploadsMiddleware                                                    │
│                                                                     │
│ 已注入:                                                              │
│ - uploaded_files: ["sales_data.csv"]                                 │
│ - virtual_path: /mnt/user-data/uploads/sales_data.csv               │
│                                                                     │
│ LLM 可感知: 用户上传了 sales_data.csv                                │
└──────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌──────────────────────────────────────────────────────────────────────┐
│ LLM 推理                                                             │
│                                                                     │
│ 分析请求需要:                                                        │
│ 1. 读取 CSV 文件 → read_file                                         │
│ 2. 生成图表 → 这个...LLa 没有直接生成图表的工具                        │
│                                                                     │
│ 决策:                                                               │
│ Step 1: read_file("/mnt/user-data/uploads/sales_data.csv")          │
│         → 读取文件内容                                               │
│                                                                     │
│ Step 2: ask_clarification(                                           │
│           "您想要生成什么类型的图表？                                   │
│            1. 折线图（显示趋势）                                       │
│            2. 柱状图（比较数据）                                       │
│            3. 饼图（显示占比）                                        │
│            4. 其他需求"                                               │
│         )                                                            │
│         → 中断执行，等待用户回复                                       │
│                                                                     │
└──────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌──────────────────────────────────────────────────────────────────────┐
│ ClarificationMiddleware 拦截                                          │
│                                                                     │
│ ask_clarification 被 ClarificationMiddleware 拦截:                   │
│     → Command(goto=END) 中断 LangGraph 执行                           │
│     → 向用户返回澄清问题                                               │
│                                                                     │
│ 用户在 UI 上选择 "折线图"                                             │
│                                                                     │
└──────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌──────────────────────────────────────────────────────────────────────┐
│ 继续执行                                                             │
│                                                                     │
│ LLM 根据用户选择:                                                    │
│ 1. 分析 CSV 数据                                                     │
│ 2. 生成 Python + matplotlib 代码                                     │
│    (注意：这里可能需要 bash，但假设有图表生成 MCP)                      │
│                                                                     │
│ 或者如果有 chart_mcp 工具:                                           │
│ Step X: create_chart(type="line", data=csv_data)                     │
│         → MCP 服务器生成图表图片                                       │
│                                                                     │
│ Step Y: present_files(["/mnt/user-data/outputs/chart.png"])          │
│         → 展示给用户                                                 │
│                                                                     │
└──────────────────────────────────────────────────────────────────────┘
```

### 关键点
- **ask_clarification**：当意图不明确时，主动请求用户澄清
- **ClarificationMiddleware**：中间件拦截这个工具，中断执行等待用户输入
- **UploadsMiddleware**：自动注入上传文件列表，LLM 知道有哪些文件可用

## 场景四：技能系统使用（Skills）

### 用户请求
> "我需要写一个 Python 函数来判断一个字符串是否是回文，请用测试用例验证"

### 技能配置
假设系统中有一个 `python-coding` 技能：

```yaml
# skills/public/python-coding/SKILL.md
---
name: python-coding
description: Python 编程助手，帮助编写、调试和测试 Python 代码
license: MIT
category: developer
allowed-tools:
  - write_file
  - read_file
---
```

### LLM 可用工具（注入技能后）
```
- write_file(path, content)     # 内置工具
- read_file(path)               # 内置工具
- task(subagent_type, prompt)   # 子 Agent 工具
- present_files()               # 内置工具
```

### 执行流程

```
┌──────────────────────────────────────────────────────────────────────┐
│ 用户请求                                                             │
│ "写一个 Python 函数判断回文，用测试用例验证"                          │
└──────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌──────────────────────────────────────────────────────────────────────┐
│ apply_prompt_template()                                              │
│                                                                     │
│ 系统提示词注入技能内容:                                              │
│                                                                     │
│ ## Available Skills                                                  │
│                                                                     │
│ ### python-coding                                                   │
│ 你是一个 Python 编程助手。                                           │
│ 擅长编写、调试和测试 Python 代码。                                    │
│ 使用 write_file 创建 .py 文件，                                      │
│ 使用 present_files 展示最终结果。                                     │
│                                                                     │
└──────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌──────────────────────────────────────────────────────────────────────┐
│ LLM 推理（受技能指导）                                               │
│                                                                     │
│ 技能告诉 LLM：                                                       │
│ - 用 write_file 创建 .py 文件                                        │
│ - 用 present_files 展示结果                                          │
│                                                                     │
│ 决策:                                                               │
│ Step 1: write_file("/mnt/user-data/workspace/palindrome.py",         │
│           "def is_palindrome(s: str) -> bool:\n"                     │
│           "    s = s.lower()\n"                                     │
│           "    return s == s[::-1]\n\n"                             │
│           "if __name__ == '__main__':\n"                            │
│           "    # 测试用例\n"                                          │
│           "    print(is_palindrome('radar'))  # True\n"             │
│           "    print(is_palindrome('hello'))  # False\n")            │
│                                                                     │
│ Step 2: present_files(["/mnt/user-data/workspace/palindrome.py"])   │
│         → 展示代码给用户                                              │
│                                                                     │
└──────────────────────────────────────────────────────────────────────┘
```

### 关键点
- **技能影响 LLM 行为**：技能通过系统提示词告诉 LLM 如何正确使用工具
- **无 bash**：代码写入文件后，通过 `present_files` 展示给用户（用户自己运行）
- **allowed-tools**：技能可以限制 LLM 能使用的工具范围

## 场景五：子 Agent 委托（Subagent）

### 用户请求
> "帮我对比分析 A 公司和 B 公司的财务报告，生成对比分析报告"

### 子 Agent 配置
```yaml
# config.yaml
subagents:
  enabled: true
  max_concurrent_subagents: 3

builtins:
  - name: general-purpose
    description: 通用任务处理
```

### LLM 可用工具
```
- task(subagent_type, prompt, max_turns)   # 委托子 Agent
- present_files()                           # 展示结果
```

### 执行流程

```
┌──────────────────────────────────────────────────────────────────────┐
│ 用户请求                                                             │
│ "对比分析 A 公司和 B 公司的财务报告..."                               │
└──────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌──────────────────────────────────────────────────────────────────────┐
│ LLM 推理                                                             │
│                                                                     │
│ 分析: 这个任务可以分解为两个独立子任务                                 │
│ - 分析 A 公司财务报告                                                │
│ - 分析 B 公司财务报告                                                │
│                                                                     │
│ 决策:                                                               │
│ Step 1: task(                                                     │
│           subagent_type="general-purpose",                         │
│           prompt="分析 A 公司财务报告，提取关键指标...",              │
│           max_turns=5                                              │
│         )                                                           │
│                                                                     │
│ Step 2: task(                                                     │
│           subagent_type="general-purpose",                         │
│           prompt="分析 B 公司财务报告，提取关键指标...",              │
│           max_turns=5                                              │
│         )                                                           │
│                                                                     │
│ Step 3: 对比两个结果，生成对比报告                                   │
│                                                                     │
│ Step 4: present_files(["/mnt/user-data/outputs/comparison.md"])     │
│                                                                     │
└──────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌──────────────────────────────────────────────────────────────────────┐
│ SubagentLimitMiddleware                                             │
│                                                                     │
│ max_concurrent_subagents=3                                         │
│                                                                     │
│ 两个 task() 调用可并行执行（≤3），                                   │
│ SubagentExecutor 管理后台线程池执行                                  │
│                                                                     │
└──────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌──────────────────────────────────────────────────────────────────────┐
│ 子 Agent 执行细节                                                    │
│                                                                     │
│ SubagentExecutor                                                    │
│     │                                                               │
│     ├── _scheduler_pool (3 workers)                                 │
│     └── _execution_pool (3 workers)                                │
│              │                                                      │
│              ├──▶ 子 Agent A: 分析 A 公司                             │
│              │         → tavily_search("A 公司 财务报告")            │
│              │         → firecrawl_scrape(url)                      │
│              │         → 返回分析结果                                │
│              │                                                      │
│              └──▶ 子 Agent B: 分析 B 公司                             │
│                  → tavily_search("B 公司 财务报告")                  │
│                  → firecrawl_scrape(url)                            │
│                  → 返回分析结果                                       │
│                                                                     │
└──────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌──────────────────────────────────────────────────────────────────────┐
│ 主 Agent 汇总                                                        │
│                                                                     │
│ 汇总两个子 Agent 的分析结果:                                         │
│ - A 公司: 收入增长 10%，利润率 15%...                                │
│ - B 公司: 收入增长 5%，利润率 22%...                                 │
│                                                                     │
│ 生成对比报告                                                         │
│                                                                     │
└──────────────────────────────────────────────────────────────────────┘
```

### 关键点
- **任务分解**：主 Agent 将任务分解为多个子任务并行处理
- **子 Agent 独立执行**：每个子 Agent 可以独立调用工具（搜索、爬取等）
- **无主 Agent 沙箱调用**：子 Agent 执行过程中，主 Agent 等待，不直接调用沙箱
- **SubagentLimitMiddleware**：限制并发数量，防止资源耗尽

## 场景六：记忆系统 + 上下文理解

> "继续上次的工作，帮我完善那个项目计划"

- **无特殊工具**：只需 `read_file` 和 `write_file`，工具本身很普通

## 场景七：图片理解（ViewImageMiddleware + Vision 模型）

### 用户请求
> "帮我看看这张图片里有什么"

### 前置条件
```
用户上传: diagram.png
模型配置: supports_vision: true
```

### LLM 可用工具
```
- view_image(path)            # 注入 base64 图片数据
- present_files()              # 展示结果
```

### 执行流程

```
┌──────────────────────────────────────────────────────────────────────┐
```

## 总结：工具选择决策矩阵

| 用户场景 | LLM 选择的工具 | 工具类型 |
|----------|---------------|----------|
| 提取网页内容 | `read_url` | MCP (Jina) |
| 搜索信息 | `tavily_search` | 社区工具 |
| 抓取网页 | `firecrawl_scrape` | 社区工具 |
| 搜索图片 | `image_search` | 社区工具 |
| 理解图片 | （Vision 模型原生） | 内置 |
| 查看上传图片 | `view_image` | 内置 |
| 读取已上传文件 | `read_file` | 内置 |
| 写入代码/文档 | `write_file` | 内置 |
| 展示结果 | `present_files` | 内置 |
| 技能辅助编程 | `write_file` + 技能提示 | 内置+技能 |
| 复杂任务分解 | `task` (subagent) | 内置 |
| 意图不明确 | `ask_clarification` | 内置 |
| 上下文记忆 | （自动注入） | 中间件 |
| 子 Agent 并行 | `task` | 内置 |
| 危险操作 | GuardrailMiddleware | 安全 |

## 核心设计原则

1. **LLM 是决策者**：工具选择由 LLM 根据系统提示词和可用工具描述决定
2. **工具描述驱动**：清晰、全面的工具描述帮助 LLM 做出正确决策
3. **MCP 封装复杂逻辑**：复杂的外部服务调用被 MCP 封装，LLM 只需调用接口
4. **中间件处理横切关注点**：记忆、护栏、图片注入等由中间件处理
5. **技能指导行为**：技能通过系统提示词指导 LLM 如何正确使用工具
